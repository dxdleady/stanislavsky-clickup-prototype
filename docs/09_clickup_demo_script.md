# Сценарий живого ClickUp-демо (реальный round-trip, ~10-15 мин настройки + сам звонок)

> Цель — не мокап руками, а рабочий срез: `demo/seed.py` наполняет реальную ClickUp-доску, на звонке вы пишете **любой свой комментарий** на любой активной задаче, сервер реально его классифицирует (Claude Haiku 4.5) и отвечает через реальные ClickUp API-вызовы. Полное техническое описание — `11_live_demo_architecture.md`. Данные не придуманы — переложены из `docs/source/stanislavsky_costume_demo_dataset_v2.json`.

## Подготовка (один раз, ~35-45 мин)

Полный чек-лист — `11_live_demo_architecture.md` §3. Коротко: статусы в ClickUp UI (`In Generation`, `Regenerate`, `Cost Approval`, `Accepted`), отдельный бот-аккаунт (Member, не Guest), `ANTHROPIC_API_KEY` + `CLICKUP_TOKEN` в `.env`.

## Перед каждым звонком (~10-15 мин)

```bash
python -m demo.seed                             # ПЕРВЫМ — см. порядок ниже
uvicorn inbound.webhook:app --port 8000         # терминал 1
ngrok http 8000                                  # терминал 2 — берёт новый URL при каждом запуске
python -m demo.register_webhook <ngrok-url>      # регистрирует вебхук на taskCommentPosted
```

`demo/seed.py` идемпотентен — можно гонять сколько угодно раз, доска каждый раз выглядит одинаково.

**Порядок важен (найдено ревью 2026-08-13, было наоборот в этом документе):** `inbound/webhook.py` читает `demo/task_map.json` (метка → реальный ClickUp id) **один раз при старте**, не перечитывает его на каждый вебхук. Если `demo.seed` запустить ПОСЛЕ `uvicorn`, сервер будет работать со старым/пустым `task_map.json` весь звонок — комментарии на новых задачах не распознаются как известные, тихо игнорируются. Если всё же перезапустили сид при уже поднятом сервере — перезапустите и uvicorn тоже.

## Задачи на доске

| Задача | Хозяин | Состояние | Для живого комментария |
|---|---|---|---|
| SC-042/07 | 🎨 Художник по костюмам | `Accepted` | Нет — "как выглядит спокойная задача" |
| SC-042/08 | 🎨 Художник по костюмам (+Continuity) | `Regenerate` | Да |
| SC-042/09 | 💰 Продюсер | `Cost Approval` | Да |
| SC-041/02 | 📋 Первый ассистент | `Blocked` | Да |

Каждая уже приходит с реальной историей комментариев (`SEED_COMMENTS` в `demo/statuses.py`) — не пустая карточка.

## Что происходит на живом комментарии

Выберите любую из трёх активных задач, напишите комментарий своими словами (как супервайзер на площадке — не нужно подбирать "правильные" слова под систему). В реальном времени на доске:

1. **📋 Первый ассистент** отвечает первым — коротко называет, к кому это относится.
2. Через ~2-3 секунды — **нужный агент** отвечает по существу и (если применимо) меняет статус карточки.

Если комментарий реально не по адресу текущей задачи (например, вопрос про график на костюмной карточке) — вместо ответа в этой же задаче создаётся **новая задача**, назначенная нужному агенту.

Таймаут классификатора — 3.5 секунды, с fallback на хозяина задачи по умолчанию при любом сбое сети/модели — демо не виснет.

## План Б — если живой вызов LLM не хочется рисковать на звонке

Ничего переключать не нужно: та же доска уже показывает историю (комментарии, засеянные `demo/seed.py`) — можно просто открыть карточку и читать вслух, ничего не печатая. Раньше это было основным путём демо (см. историю этого документа) — теперь это план Б, живой комментарий на реальной задаче основной.

## Итог на доске

Четыре карточки в четырёх разных состояниях — доска сама показывает разнородность с первого взгляда, до того как открыт хоть один комментарий. Одна показывает "спокойный" итог (Accepted), три доступны для живого вмешательства прямо на звонке.
