# CLAUDE.md

Рекомендации по коду для этого репозитория. Консолидирует правила, установившиеся по ходу работы (детали и обоснование — в `docs/01_architecture_plan.md`, `docs/07_grilled.md`, `docs/08_dataset_analysis.md`).

## Архитектурные границы

- **`prototype/core/` не импортирует из `adapters/`, `inbound/`, `agents/`.** Если для новой фичи нужно туда лезть — сигнал, что абстракция неверна, не повод сделать исключение.
- **Время только через `core/clock.py::Clock`** (инъекция, не глобал) — никаких `datetime.now()`/`time.sleep()` внутри `core/`/`inbound/`. Иначе тесты на батчинг/дедлайны становятся медленными и нестабильными.
- **`Stage` — не enum.** Легальные значения и переходы всегда задаёт `core/state_machine.py::WorkflowConfig`, никогда не хардкодить набор статусов конкретного домена в коде общего назначения. В репозитории уже две независимые конфигурации (`CAMERA_PIPELINE`, `COSTUME_PIPELINE`) — это не совпадение, а доказательство, что архитектура выдерживает больше одного домена. Третий домен добавляется новой конфигурацией, не правкой существующего кода.
- **Никакого `eval()`** на конфиг-условиях (`filter_config.yaml` и подобное) — только безопасный интерпретатор сравнений.
- **`AgentEvent.payload` остаётся нетипизированным `dict`.** Не пытаться навязать единую схему — разнородность входа агентов (и людей) осознанное свойство системы (P2 ТЗ), подтверждено на практике в разговоре с пользователем ("задачи от Тимура тоже прилетают хаотично"). Нормализация к конверту происходит в `agents/*`, не в контракте.
- **`post_comment` vs `post_reply`** в `adapters/clickup.py` — разные endpoint'ы ClickUp API, не параметры одного метода. Не объединять.

## Точки расширения — контракт, не хардкод

- Новый агент → адаптер под `agents/*`, эмитящий `AgentEvent`.
- Новый трекер (не ClickUp) → новый класс, реализующий `TrackerAdapter` (`adapters/base.py`).
- Новая политика роутинга/фильтра → конфиг или новая реализация за тем же интерфейсом (`Router`, `Filter`).

Если для очередной фичи требуется трогать `core/` — это сигнал, что где-то нарушена изоляция, не повод сделать исключение (см. `docs/01_architecture_plan.md` §9).

## Допущения

Любое архитектурное решение, не подтверждённое исходными материалами (ТЗ/архитектура/деки/датасеты), помечается в коде комментарием вида `# ASSUMPTION(open_questions:XX): ...` со ссылкой на конкретный пункт `docs/06_open_questions.md`. Так при получении реального ответа легко найти все места, которые нужно пересмотреть: `grep -r "ASSUMPTION(open_questions"`.

## Тесты

- `adapters/memory.py` + `core/clock.py::FakeClock` — никогда реальный `sleep()` и никогда реальный ClickUp в юнит-тестах.
- Сценарий/тест пишется до реализации (sim/scenario-driven), не после.
- Сетевые вызовы (ClickUp API, Anthropic API) в юнит-тестах — мокать; интеграционные проверки с реальными токенами — отдельно, вручную (см. чек-листы в `docs/09_clickup_demo_script.md`, `docs/11_live_demo_architecture.md`).

## Демо-код — не исключение

Живой демо-слой (`inbound/webhook.py`, `agents/live_demo_agent.py`, `demo/*`) построен под сжатый срок, но следует тем же правилам там, где это дёшево: реальные `AgentEvent`, реальный `WorkflowConfig`, реальный `TrackerAdapter`. Очередь с ретраями (`core/outbound_queue.py`) и `Filter` (`core/filter.py`) теперь реализованы (не заглушки) — что по-прежнему сознательно упрощено (HMAC-проверка выключена по умолчанию) — помечено явно в коде и в `docs/11_live_demo_architecture.md`, не оставлено молчаливым сокращением.

## LLM-клиент — только через `core/llm.py`

Любой код, которому нужен вызов LLM (сейчас — Qwen, OpenAI-совместимый эндпоинт), берёт клиент через `core/llm.py::build_client()`/`complete_text`/`complete_structured`, не конструирует SDK-клиент инлайном в `agents/*`/`inbound/*`. Это уже было нарушено один раз (Anthropic-клиент собирался в трёх разных местах) — расхлёбывать пришлось при смене провайдера. `core/llm.py` не глотает исключения — таймаут/сеть/невалидный ответ пробрасываются вызывающему коду, у которого есть свой fallback (см. `classify_comment`/`generate_reply`).

## Секреты

Только через `.env`/переменные окружения (`core/config.py`), никогда не хардкод. `.env` — в `.gitignore`, коммитится только `.env.example` с именами переменных без значений.

## Стиль

- Комментарии — только там, где не очевиден WHY (скрытое ограничение, обходной путь, неочевидное решение). Не описывать WHAT — имена уже это делают.
- Type hints везде; pydantic-модели для данных, пересекающих границы модулей.
- Один `pyproject.toml` (`prototype/`) — источник правды по зависимостям.
